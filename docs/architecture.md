# 네이티브 앱 구조

Android Java Activity/View/Canvas로 구현하며 WebView나 웹 프론트엔드를 사용하지 않습니다. Android 8.1/API 27 이상, ARM64 우선이며 x86_64는 에뮬레이터 검증용입니다. iOS는 이번 구현 범위에 포함하지 않습니다. 시스템의 라이트/다크 모드에 따라 색상과 네이티브 다이얼로그가 변경됩니다.

`HomeActivity`에서 대국과 기록을 선택합니다. `GameSetupActivity`는 상대 난이도를 스크롤하고 대국 시작 버튼을 하단에 고정합니다. `ImportActivity`는 기록 안에서 PGN/SAN/UCI 붙여넣기·파일 열기를 제공합니다. 대국과 복기 화면 상단에 AI 조언과 모델 선택을 고정하고, `PieceRenderer`의 채움 벡터와 `BoardView`의 색상·기호·화살표를 공유합니다.

`Chess`는 합법 수·체크·캐슬링·앙파상·4종 승격·SAN을 처리합니다. 무승부는 기물 부족, 스테일메이트, 3회 반복 및 50수 규칙을 처리하며 반복/50수는 앱에서 자동 청구하는 정책입니다. `Pgn`은 표준 PGN의 메인 라인 및 SAN, 좌표 UCI 시퀀스를 읽습니다. 태그와 FEN 시작 국면을 지원하고 주석·NAG·가지 변화는 건너뜁니다. 한 번에 한 대국, 최대 600반수를 가져옵니다.

`Stockfish`는 APK에서 추출된 네이티브 executable을 UCI 자식 프로세스로 실행합니다. 분석 프로세스는 항상 `Skill Level=20`, `UCI_LimitStrength=false`입니다. 대국 상대는 별도 프로세스이고 설정된 Skill/Elo만 변경합니다. 입문 Skill 0, Elo 1320/1600/2000/2400/2800/3190, 제한 없는 최강을 제공합니다. Elo는 엔진의 목표치로 다른 사이트의 실전 레이팅과 동일하지 않습니다. 탐색 시간과 하드웨어에 따라 결과는 달라집니다. 실력 제한이 없다는 것과 무한한 깊이를 계산한다는 것은 다릅니다.

`Records`는 앱 내부 SQLite에 직접/가져온 대국을 함께 저장합니다. 수순은 PGN/SAN/UCI와 FEN으로 재구성되며 각 반수에 `details`(Stockfish 후보/PV/평가/메이트/깊이, 실전 수 평가, 착수 후 분석), 모델 입력 `payload`, 실제 `aiResponse`(모델·해설·사용량)와 `aiByModel`(모델별 해설 캐시), 화면용 해설을 저장합니다. 늦게 도착한 해설은 해당 반수에 병합하며 다른 수의 엔진 분석을 덮어쓰지 않습니다. 기록은 새 대국 후에도 남습니다. 무르기는 현재 기록에서 제거된 반수의 분석과 하이라이트도 제거합니다.

`RecordsActivity`가 두 출처를 같은 화면에서 보여주며 `ReviewActivity`에서 수순을 눌러 이동하거나 이전/다음으로 탐색합니다. 가져온 대국은 전체 Stockfish 분석 후 하이라이트를 생성합니다. 직접 둔 대국도 같은 전체 분석/하이라이트 버튼을 제공합니다. 이미 저장된 엔진 분석과 동일 모델의 해설은 재사용합니다. 복기 화면을 닫으면 진행 중 작업은 중단하며 완료된 결과는 남습니다. 작업 재개 버튼으로 이어갈 수 있습니다. 현재 버전은 분석 서비스를 백그라운드에서 무기한 실행하지 않습니다.

`ChatGptLoginService`는 로그인 중에만 foreground 알림과 `127.0.0.1` 수신기를 유지합니다. fresh state/nonce/PKCE를 메모리에 생성하고, 공식 동적 등록에서 받은 client ID로 코드를 교환합니다. `ChatGptProtocol`은 콜백·RS256/JWKS ID 토큰·허용 scope와 SSE 완료를 검증합니다. `ChatGptStore`는 전체 계정 기록을 Keystore AES-GCM으로 암호화해 AtomicFile로 교체합니다. `ChatGptAccounts`는 계정별 등록, 단일화한 토큰 갱신, 모델 목록, 로그아웃을 처리합니다. 네트워크 갱신 중에도 UI의 계정 조회를 막지 않으며 계정 변경·로그아웃 뒤 늦게 도착한 결과는 버립니다.

`CoachClient`가 공개 `https://api.openai.com/v1/responses`를 OAuth bearer로 직접 호출합니다. `store:false`, `stream:true`, stateless input과 짧은 엔진 근거를 보내며 `response.completed` 없이 끝난 응답은 DB에 저장하지 않습니다. `/v1/models`의 표시용 모델만 사용합니다. 서버, Codex CLI, 비공개 backend-api, API 키와 별도 API 과금 경로는 사용하지 않습니다. 구독 한도 초과 후 새 요청을 중단하고 사용자에게 ChatGPT 사용량 관리를 안내합니다. 구독 사용 허용 여부는 identity 로그인과 별도로 검사합니다.

모바일 로컬 OAuth는 PKCE를 사용하더라도 OS가 앱 프로세스를 종료하면 재시도해야 합니다. Android 고유의 브라우저 전환과 foreground service 정책은 실기기 검증 대상이며, 실제 계정 동의·모델 응답은 연결 화면의 최소 기능 테스트로 확인합니다. [직접 인증 검증 절차](siwc-android.md)를 참고하세요.

LLM 해설은 제한된 엔진 검색에 대한 해석입니다. `MoveJudgment`는 최선수와 평가 손실을 색상·기호로 표시합니다. 충분한 탐색 깊이, 합법적인 PV에서의 기물 희생, 보상 평가를 모두 만족할 때만 ‘탁월 후보’로 표시합니다. 확정 판정이나 Chess.com과 동일한 기준이라고 주장하지 않습니다. 전략적 근거가 PV로 증명되지 않으면 추정임을 표시하도록 요청합니다. 모델의 설명을 완전한 체스 증명으로 보장하지 않습니다.

## AI 표시와 요청 우선순위 (0.4.0)

`CoachPanel`은 대국/복기 공통 요약과 상세 다이얼로그를 관리합니다. 팝업 전체가 같은 시스템 테마 surface를 사용하고 마크다운은 WebView 대신 네이티브 텍스트 span으로 표시합니다. `CoachText`는 SSE의 부분 JSON 문자열을 디코딩하며 불완전한 이스케이프와 JSON 키를 화면에 노출하지 않습니다. 부분 문자열은 화면 상태에만 두고 완료 이벤트와 최종 JSON 검증을 통과한 응답만 저장합니다.

기본 요청은 `summary` 하나를 받습니다. 상세 버튼은 기존 후보와 PV를 그대로 보내 `flow`, `bestMoveReason`, `plan`을 받습니다. `Records.explanation`은 동일 모델의 기존 필드를 병합하고 `summaryUsage`, `detailUsage`를 함께 보관합니다. 기존 버전의 3필드 해설과 텍스트 캐시도 읽을 수 있습니다. `CoachQueue`는 한 요청만 실행하고 선택한 수의 요청을 대기 중 일괄 복기보다 우선합니다. 모델·수 이동에는 화면 키/요청 버전으로 오래된 스트리밍을 차단하고 무르기는 남은 요청도 무효화합니다.
